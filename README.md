# Marketing Agency Team

نظام تعليمات عربي محمول لتنظيم Lead ومتخصصي SEO وAds وTechnical وDeveloper (WordPress أو Custom/Laravel)، مع Reviewer وInfrastructure وMeasurement عند الحاجة. هذه تعليمات مشروع، وليست تطبيقًا أو تسجيل Agents دائمين أو ضمان اتصال حسابات.

## فتح النسخة وتجهيزها

```bash
git clone https://github.com/marwa-mrwan/Marketing-Agency-Team.git
cd Marketing-Agency-Team
python3 scripts/verify_package.py
```

بعد نشر المالك للنسخة المراجعة، يمكن تنزيلها بالأوامر أعلاه. قبل النشر افتح مجلد الحزمة المحلية مباشرة؛ لا تفترض أن upstream يحتوي تحديثات هذا الإصدار. بدون Git: افتح [المستودع](https://github.com/marwa-mrwan/Marketing-Agency-Team)، ثم Code → Download ZIP وفك الضغط وافتح المجلد في المساعد. يتطلب فحص الحزمة Python 3.9+ فقط، بلا مكتبات خارجية أو اتصال شبكة.

## الإعداد في بيئة جديدة

1. افتح مجلد الحزمة كـworkspace في مساعد يدعم تعليمات المشروع. اقرأ [نقطة الدخول](<AGENTS.md>) و[دليل الفريق](<agency-team/README.md>) و[Lead](<agency-team/roles/lead.md>). إذا لم يحدث auto-loading، اطلب قراءتها صراحة؛ أسماء الأدوات في المستندات وصفية وتتكيف مع المضيف الفعلي.
2. راجع [مصادر Skills](<SKILLS.md>) وثبّت فقط المهارات اللازمة وفق تعليمات المصدر والمضيف، بعد مراجعة الكود والترخيص والصلاحيات. لا توجد Skills مجمعة هنا، ولا تثبيت تلقائي، ولا ضمان تطابق تعديلات محلية مع upstream. لا تنفّذ installer خارجيًا دون مراجعة.
3. افحص كتالوج المهارات وأدوات Team والموديلات والاتصالات المتاحة فعليًا. إذا لم توجد أدوات Team، اذكر القيد؛ لا توعد بأعضاء ظاهرين أو دائمين. وجود التعريفات على القرص لا يعني بقاء أعضاء أو jobs بين الجلسات.
4. أنشئ سياقًا خاصًا مستقلًا لكل عميل باستخدام [القوالب](<agency-team/templates.md>) خارج المستودع العام. عند النقل إلى مشروع قائم ادمج التعليمات يدويًا بعد المراجعة؛ لا تستبدل تعليماته أو تغييرات المستخدم تلقائيًا.
5. صِل الحساب المطلوب فقط عبر مصادقة رسمية وبإذن منفصل؛ أكد property/account والبيئة والنطاق. الحزمة لا توصل Google/GitHub/WordPress أو أي خدمة تلقائيًا. استخدم exports مصرحًا بها عند غياب الاتصال.

## ابدأ بهذا الطلب

> اقرئي AGENTS.md ثم agency-team/README.md وagency-team/roles/lead.md وخريطة agency-team/skill-routing.md. اعملي كـLead للموقع [الموقع] والهدف [النتيجة]. ابدئي بتحليل فقط، وحمّلي المهارات الفعلية الملائمة، واستخدمي المتخصصين المطلوبين فقط. أي تنفيذ حي يحتاج خطة وموافقة محددتين. أعيدي الأدلة والاختبارات المنفذة وغير المنفذة والقيود ونتيجة موحدة.

يمكن طلب متخصص واحد، مثل «مراجعة SEO لصفحة واحدة» أو «مراجعة Laravel ساكنة فقط». لا يلزم تشغيل كل الأدوار أو تحميل كل المهارات.

## التشغيل المحمول حسب القدرات

اتبع [المسار المحلي](<agency-team/local-workflow.md>)؛ لا يوافق هذا القالب مسبقًا على Delegate أو موديل لأي دور. يبدأ [قالب الدفتر](<agency-team/templates/tasks.example.json>) فارغًا بلا مهام أو موافقات أو معرّفات حقيقية. يحتفظ Lead بالدفتر الفعلي خارج الحزمة العامة؛ لا تنشره ولا تنسخ سجلات جلسة إعداد هذه النسخة.

```bash
python3 agency-team/check_local_workflow.py .
node --test native-teams/tests/model-route.test.mjs
```

الفحص الأول يعمل على القالب الفارغ افتراضيًا، ويختبر الموافقات والتبعيات وحالات الرفض بعينات اصطناعية في الذاكرة. لا يثبت موافقة حقيقية أو تكامل GUI. يتطلب Python 3.9+؛ اختبار Node يحتاج Node.js 18+ ولا يستخدم موديلات أو شبكة.

## إضافة Native لإعادة Teams واختيار موديل لكل متخصص

**تحذير rc.1:** الإضافة المحفوظة مقيدة بـDSH `0.2.2-rc.1` وليست مسار التشغيل المحمول الافتراضي. عدم توافق المضيف (`incompatible-version`) حاجز توقف، لا إذنًا لتجاوز الإصدار أو تثبيت profile. لم تُثبت الإضافة أو تُختبر GUI في إعداد هذا الإصدار. التشغيل حسب القدرات أعلاه لا يحتاجها.

كود الإضافة وأرشيفها ووثائقها محفوظة دون تعديل حتى لا تختلف عن بصماتها؛ ذكر QA داخلها اسم تاريخي مطابق لـReviewer، وليس عضوًا إضافيًا أو تجاوزًا لبوابة اختيار المستخدم. الأسماء المعتمدة وروابط التوافق في دليل الفريق.

[Native Teams](<native-teams/README.md>) إضافة تجريبية قابلة للتثبيت داخل مضيف DSH متوافق، وليست نسخة من البرنامج ولا MCP. تحفظ خدمة الفريق والأدوات التسع وواجهة roster/tasks بكود مشتق مرخص، ولا تحتاج حزم Agent Teams الأصلية. تضيف اختيار provider/model لكل دور قبل أول تشغيل، مع بقاء Lead على موديل الجلسة ورفض الاختيارات غير المتاحة دون fallback.

[حزمة التثبيت](<native-teams/dist/agency-team-native-0.1.0.tgz>) · [البصمة](<native-teams/dist/SHA256SUMS>) · [نتائج وحدود الاختبارات](<native-teams/TESTING.md>).

التوافق المسموح حاليًا `DSH 0.2.2-rc.1`؛ لا يوجد ضمان تشغيل على كل ZadLoop أحدث. حُققت دورة Team في core معزولة بموديلات اصطناعية، وليس تثبيت Desktop أو اختبار عرض GUI على جهاز آخر. راجع الدليل وابدأ بـprofile تجريبي؛ لا تتجاوز بوابة الإصدار ولا تشغّل الخدمة الرسمية والإضافة معًا.

## نسخة إنقاذ ميزة Agent Teams

أضيف [runtime-support](<runtime-support/README.md>) منفصلًا عن تعليمات الأدوار: snapshots للحزم الأربع المحلية مع MIT وبصمات وفحص offline ودليل استعادة مشروطة. **ليس MCP ولا runtime مستقلًا ولا نسخة كاملة من ZadLoop**؛ اختبار الاستقلال فشل لغياب اعتماديات DSH، كما يوضح [سجل التحقق](<runtime-support/EVIDENCE.md>). تنزيل المجلد لا يعيد الميزة تلقائيًا إذا أزيل محركها من التطبيق. يلزم استعادة تطبيق كامل متوافق أو ترحيل واختبار منفصل.

```bash
python3 runtime-support/doctor.py
python3 -m unittest discover -s runtime-support -p 'test_*.py' -v
```

هذا فحص بنيوي محلي، لا اختبار تكامل للمساعد أو auto-loading أو Skills أو اتصالات أو تنفيذ SEO/Ads/WordPress/Laravel. لا يثبت خلو أي تعديلات مستقبلية من الأسرار؛ يلزم تدقيق بشري قبل كل نشر. روابط upstream قد تتغير، وتحتاج السياسات والإصدارات إلى تحقق وقت المهمة. لم تُضف رخصة نيابة عن المالك؛ تظل تراخيص المصادر الخارجية وحقوقها سارية، ولا تُعاد تعبئة Skills هنا.
