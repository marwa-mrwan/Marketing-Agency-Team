# Native Teams — إضافة تجريبية قابلة للتثبيت

`@marwa-mrwan/agency-team-native@0.1.0` تعيد **خدمة Agent Teams والأدوات التسع وواجهة roster/tasks** كإضافة Native، وتضيف اختيار `provider/model` لكل متخصص قبل أول تشغيل له. ليست MCP، وليست نسخة من التطبيق، ولا تعتمد على وجود حزم Agent Teams الأصلية الأربع. يلزم أن يبقى محرك DSH الأساسي وآلية الإضافات وواجهات subagents/session/العميل متوافقة.

**حد التوافق:** بوابة `engines.dsh` تسمح حاليًا بـ`0.2.2-rc.1` فقط. الاختبارات على core المضمّن في ZadLoop `0.10.3`، وليس على إصدار أحدث غير معلوم. عند رفض إصدار جديد لا تتجاوز البوابة؛ يلزم إصدار جديد من الإضافة بعد اختباره. حذف أدوات الميزة فقط يختلف عن حذف خدمات المحرك نفسها. تنزيل الـrepo وحده لا يفعّل الإضافة.

## التثبيت المعتمد يدويًا

1. نزّل المستودع وافتح [حزمة التثبيت](<dist/agency-team-native-0.1.0.tgz>) بعد فحص [البصمة](<dist/SHA256SUMS>). لا تشغّل postinstall خارجيًا ولا تثبّت شيئًا في ملفات تطبيق ZadLoop نفسه.
2. استخدم profile اختباريًا منفصلًا أولًا. من Plugins عطّل bundle Agent Teams الرسمي إن كان مفعّلًا؛ لا تجمع خدمتي Team في نفس profile. لا تعدّل profiles أو جلسات العملاء، ولا تثبّت أثناء وجود أعضاء يعملون.
3. اطلب من المساعد في المضيف المتوافق فحص الـbundle المحلي ثم تثبيته عبر `plugin_manager` باستخدام **المسار المطلق للأرشيف**. العملية تحتاج موافقة صريحة وتؤثر على الـprofile كله. هذه الحزمة لا تحتوي lifecycle scripts. إذا طلبت dependency أي build script، توقف وراجعه؛ لا تمنحه إذنًا تلقائيًا.
4. إذا ظهرت `incompatible-version` أو رسالة missing core API، توقف؛ لا تمنح version exemption ولا تنسخ ملفات فوق التطبيق. إذا تطلب المضيف restart فأعد تشغيل profile الاختباري، وأعد تحميل الواجهة وافتح جلسة جديدة.
5. افحص وجود الأدوات التسع عمليًا، ثم اختر موديلًا لكل متخصص. الحسابات والموديلات والـSkills لا تُثبت ولا تُربط بهذه الإضافة؛ استخدم مزودًا مصرحًا ومتاحًا فعليًا في المضيف. لا يلزم API key جديد إن كان المضيف يتيح اتصالًا متوافقًا موجودًا، لكن الاتصال لا يُضمن.

هذه خطوات تشغيل مشروطة بواجهة الإضافات في المضيف. اختبار الحزمة في package manager وcore منفصل لا يساوي تثبيتًا ناجحًا على Desktop آخر؛ راجع [TESTING.md](<TESTING.md>) للحدود والنتائج.

## اختيار الموديل

Lead الرئيسي يظل على موديل الجلسة. قبل كل role آخر، بما فيه QA، يسأل Lead المستخدم عن الاختيار. مثال arguments للأداة الجديدة — استبدل القيم بمُعرّفات حقيقية معتمدة:

```json
{
  "name": "seo",
  "description": "SEO specialist for the approved task",
  "prompt": "Load the SEO role and actual available Skills; analyze only.",
  "context": "fresh",
  "provider": "USER_SELECTED_PROVIDER",
  "model": "USER_SELECTED_MODEL"
}
```

أو `use_session_model: true` **فقط بعد موافقة المستخدم لهذا الدور**، من دون provider/model/effort. `reasoning_effort` اختياري ويجب أن تدعمه route المختارة. اختيار غير موجود أو effort غير صالح يُرفض قبل حجز اسم العضو؛ لا تبديل تلقائي. فحص metadata قبل الإنشاء لا يضمن قبول المزود لاحقًا للطلب أو صحة credentials أو أسعار/حصص الحساب.

الإضافة تفرض وجود اختيار صريح في arguments، لكنها لا تستطيع إثبات أن محادثة الموافقة حدثت؛ يظل Lead مسؤولًا عن سؤال المستخدم. إعدادا spawn/fork داخليان منفصلان عن مزود LLM. التخصص يأتي من تعريف الدور والـSkills المحملة والأدلة، لا من مجرد اسم الموديل.

## الوظائف المحفوظة

`spawn_teammate`, `send_message`, `list_agents`, `wait_agent`, `interrupt_agent`, `team_task_create`, `team_task_list`, `team_task_get`, `team_task_update`.

الأعضاء Named continuable Agents حقيقيون داخل المحرك، وليسوا تفويضًا مؤقتًا متنكّرًا. المهام تستخدم revisions وDAG وwrite_scopes استشارية. الرسالة المقبولة لا تثبت معالجتها. عندما يكون العضو cold ولا توجد route محملة لا تعرض القائمة موديل Lead بدلًا منه؛ route الطفل محفوظة في descriptor الخاص به.

## الأمان والرجوع

كود Host يعمل داخل عملية التطبيق خارج sandbox الملفات؛ راجع [NOTICE.md](<NOTICE.md>) والكود قبل تفعيله. لا تضف حسابات أو credentials إلى repo. تشغيل المتخصصين يستخدم حدود المضيف وصلاحياته وتكلفة الموديلات المعتمدة؛ لا تمنح هذه الإضافة صلاحية نشر أو تعديل عميل.

للرجوع: انتظر اكتمال/إيقاف العمل التجريبي، عطّل bundle `@marwa-mrwan/agency-team-native` من Plugins، وأعد التشغيل إذا طلب المضيف. يمكن إعادة تفعيل bundle الأصلي إن كان متاحًا ومتوافقًا بعد تعطيل الإضافة. لا تحذف مخزن الجلسات ولا تعمل downgrade فوق بيانات عدلها إصدار أحدث. تنسيق أحداث Team المرجعي محفوظ، لكن الرجوع الفعلي بين إصدارات Desktop غير مختبر.
